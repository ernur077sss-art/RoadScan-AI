# RoadScan · Народный контроль дорог

## Этап 1: продуктовый контракт

Один устанавливаемый веб-сервис. Житель: телефон + пароль без SMS → фото/короткое видео → точка или описание места → номер обращения → решение инспектора. Инспектор: очередь → материалы → уточнение места → решение → ответ жителю. ИИН не собираем.

### Роли
- citizen: только собственные обращения и вложения; дополнение по запросу инспектора.
- inspector: очередь города, просмотр материалов, решения, координаты и связи.
- admin: права инспектора плюс назначение ролей через защищённый API/операторскую CLI.
Роль не передаётся при регистрации. Публичной карты с персональными данными нет.

Житель может зарегистрироваться с PIN ровно из 4 цифр или выбрать длинный пароль (15–128 символов). Доступ сотрудников требует длинного пароля; PIN-аккаунтам такие роли не назначаются. Ранее созданные пароли действуют без изменений. Номер не подтверждается через SMS.

### Экраны
`/` — обзор сервиса и действие «Сообщить»; `/login` — телефон, пароль, согласие при регистрации; `/reports/new` — материалы, описание, карта, черновик; `/reports` — мои обращения; `/reports/[id]` — материалы, история, ответ и уточнение; `/inspector` — очередь, карта, KPI; `/inspector/reports/[id]` — проверка и решение; `/privacy` — сведения о локальном демонстрационном режиме и требования к оператору пилота.

### Данные и статусы
Observation — оригинальное обращение. Incident — уникальный подтверждённый дефект. Несколько наблюдений могут ссылаться на один incident. WorkOrder оставлен для будущего управления ремонтом, сейчас не создаётся.

Статусы обращения: pending → needs_info / confirmed / rejected. needs_info → pending после уточнения жителем. Отклонение и запрос уточнения требуют текста причины. Инспектор может пересмотреть решение с причиной и версией записи; изменение связи протоколируется. confirmed не означает устранение.

Геопозиция устройства и предполагаемая точка дефекта различаются. Точку можно указать вручную. Неточное место не блокирует регистрацию физически существующего дефекта: location_verified=false. Подтверждённый без точки дефект остаётся в KPI. Автоматического объединения только по радиусу нет.

### Инварианты
- UNIQUE(author_id, event_id); одинаковый payload возвращает тот же результат, другой payload с тем же ключом — 409.
- Медиа принадлежит автору, связывается с обращением транзакционно; повторы не создают сирот.
- Исходные наблюдения сохраняются при смене связи. Дефект без связанных подтверждённых обращений архивируется и исключается из текущего реестра с историей.
- Изменение инспектором проверяет version; конфликт возвращает 409.
- Начало ожидания = received_at сервера; повтор доставки не меняет его.
- KPI за период создания incident = verified active incidents / all active incidents × 100. Пустой знаменатель — null, а не 100. Нет точки — не verified. Цель ≥90%; измерять на пилоте.

### Границы
Категории: яма, разрушение покрытия, повреждённый/открытый люк, другая дорожная проблема. Категория не является автоматической оценкой опасности. Фото: JPEG/PNG/WebP; видео: MP4/WebM/MOV, проверка контейнера и продолжительности. HEIC требует преобразования пользователем в текущей версии. До 4 вложений, 25 MB на файл, видео до 30 секунд. Точные эксплуатационные лимиты пилота пересматриваются после измерений.

Сбор с транспорта, ИИ-инференс, подрядчики, публичная карта и магазины приложений не входят в этот MVP. Реальная 109-интеграция зависит от документированного API. Номер служит логином без проверки владения SIM; SMS-провайдер для бесплатной версии не требуется. До приёма реальных данных нужен оператор персональных данных и согласованный контур хранения.
