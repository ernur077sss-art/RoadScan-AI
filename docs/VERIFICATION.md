## Серверные сценарии

- Одноразовость OTP, истечение срока, пять неудачных попыток, частота запросов и обязательное согласие.
- Выход и истёкшая сессия, запрет назначения роли жителем, запрет чтения чужого обращения/медиа и материалов дефекта.
- Одинаковый повтор отправки возвращает прежнюю запись и время; изменённое тело с тем же ключом отклоняется. Два параллельных запроса создают одно обращение.
- Вложения принадлежат автору, чужие/использованные файлы отклоняются. Поддельное изображение не принимается.
- Реальный небольшой MP4 перекодируется и выдаётся приватно, длинное видео отклоняется; приватный S3 Range проверен имитацией клиента, без реального bucket.
- Запрос уточнения → ответ жителя → подтверждение; устаревшее решение отклоняется. Изменение точки имеет собственную версию и историю.
- KPI учитывает уникальные дефекты и отсутствие точки. Перепривязка не оставляет пустой объект в знаменателе; нулевой знаменатель возвращает отсутствие данных.
- 109 simulator выдаёт только `DEMO-109-*` и `simulated`; отключённый адаптер не заявляет успешную отправку, повторы ограничены.
- SMS bridge проверен заглушками принятия/отказа: код не возвращается в API-ответе, при отказе challenge недействителен. Это не тест доставки реального SMS.
- Backup восстанавливается в отдельную папку с чтением сессии, обращения и изображения. Повреждение вложения выявляется контрольной суммой.
- Зафиксированная начальная миграция применена к чистой SQLite-базе; после неё создано обращение.

## Браузерные сценарии

1. Вход по телефону на ширине 375 px → создание с вложением и ручными координатами → обновление страницы → восстановление черновика → сервер принимает обращение, ответ искусственно теряется → безопасный повтор → ровно одна запись. В другом профиле инспектор запрашивает уточнение, житель отвечает, инспектор подтверждает, KPI и карта обновляются. Третий аккаунт не получает чужие данные.
2. Главная на 375, 768 и 1280 px без горизонтального переполнения; тёмная тема сохраняется; доступ к содержимому с клавиатуры; manifest и иконки доступны; при отключении сети сервис-воркер показывает офлайн-страницу.

Проверены скриншоты главной в двух темах, мобильной формы и рабочего места инспектора. Отчёт Playwright находится в `web/playwright-report/`, скриншоты — в `web/test-results/`; это локальные результаты, не исходники. Браузерные тесты запускают dev-сервер; production-сборка проверена отдельно и запущена через standalone server. Контрольный просмотр собранной главной, API health и запрета создания до входа выполнен в Chrome.

- 5 тестов конфигурации: локальный/Docker API, обязательный HTTPS-host на Vercel, отказ для localhost и примеров, запрет URL с паролем/путём, защита от проксирования фронтенда в самого себя.
- Сборка Next.js с `VERCEL=1` и тестовым HTTPS-origin прошла; в `routes-manifest.json` проверены внешний `/api/*` rewrite и три заголовка `no-store`. Сборка не обращается к тестовому адресу и не публикует проект.

- TypeScript, 28 серверных тестов и 2 браузерных сценария повторно прошли; PostGIS по-прежнему пропущен локально.
- Скрипт запуска API испытан на отдельном локальном порту `8121` и временной SQLite-базе: применены миграции до текущего Alembic head, `/api/health` вернул `ok`, процесс корректно остановлен. Это проверка entrypoint, не Docker-образа.

## Что ещё не подтверждено

Не выполнялись: реальная SMS-доставка, контракт и передача в 109, работа реального S3, Docker/PostGIS, удалённый GitHub Actions, публичное HTTPS-развёртывание, физические Android/iPhone, нагрузочные испытания, внешний аудит безопасности и городской пилот. Приложение нельзя называть готовым к публичной эксплуатации только на основании локальных тестов.

В серверном тестовом окружении есть предупреждение Starlette о будущем переходе TestClient с httpx на httpx2; тесты проходят. Плановое обновление тестового транспорта следует выполнить при обновлении зависимостей.


## Бесплатный стенд и пароль — этапы 2, 3 и 8

Проверено локально 11 октября 2026:

- 38 серверных тестов прошли, 1 PostGIS-тест пропущен. Регистрация с согласием, длинные пароли с Unicode/пробелами, salted scrypt, приватность телефона, повторный вход после перезапуска, cookie Secure/HttpOnly/SameSite и запрет самоназначения роли.
- Неверный пароль и неизвестный аккаунт дают одинаковую ошибку; лимит неудачных входов сохраняется между перезапусками. OTP-пути закрыты в режиме пароля. Старый OTP-аккаунт и зарегистрированный пароль нельзя перезаписать повторной регистрацией.
- Миграции повторяемы; переход с `0001` на `0002` сохраняет старого инспектора без назначения ему пароля или признака подтверждённого телефона.
- Реальный botocore signer проверен без сети: Supabase path-style endpoint сохраняет `/storage/v1/s3`, SigV4, срок подписанного URL 60 секунд. Это не испытание реального S3.
- 3 браузерных сценария прошли: неверный пароль/выход/повторный вход и redirect, регистрация и полный путь обращения/инспектора, адаптивность/темы/PWA. TypeScript и production-сборка прошли.

Локальная база обновлена до `0002` после создания проверенной резервной копии; прежние обращения сохранены. Собранная форма входа и регистрации просмотрена в браузере, локальный API работает в режиме `password`.

PostgreSQL session lock мигратора, Supabase Data API/Storage и Render Docker требуют облачной проверки. Наличие `render.yaml` с `plan: free` не означает, что сервис развёрнут. Восстановление забытого пароля пока не реализовано. Облачные ресурсы и публичная ссылка ещё не готовы.
